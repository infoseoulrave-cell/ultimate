# 에이전트 설계: 로컬 제어 + API 지능 + 따뜻한 페르소나

## 목표

- **로컬 통합 제어**: openclaw와 같은 방식으로 로컬 컴퓨터를 단일 제어면에서 통합 제어.
- **자유도**: 확장 가능한 도구·플러그인, 제약 최소화.
- **API 두뇌**: 외부/내부 API를 활용한 판단·기억·실행.
- **따뜻한 감정**: NEXUS(구조적 판단)와 사용자 대면 시 따뜻한 톤·감정 레이어.

---

## 1. 레이어 구조

| 레이어 | 역할 | 구현 방향 |
|--------|------|------------|
| **제어 (Control)** | 로컬 리소스·프로세스·파일·쉘·디바이스 접근 | openclaw 스타일 통합 어댑터, 권한·샌드박스 정책 |
| **지능 (Brain)** | 목적 해석, 계획, 도구 선택, API 호출 | LLM/에이전트 API, 도구/함수 호출, 상태·컨텍스트 관리 |
| **페르소나 (Persona)** | 대화 톤, 감정 표현, 사용자 경험 | 시스템 프롬프트·페르소나 설정, 응답 포맷(따뜻함 + 명료함) |

NEXUS/CSA는 **전략·의사결정 로직**을 정의하고, 위 세 레이어가 그 로직에 맞게 동작하도록 설계한다.

---

## 2. 로컬 통합 제어 (openclaw 스타일)

- **통합 인터페이스**: 키보드·마우스·앱·파일·네트워크·시스템 설정 등을 하나의 제어 모델로 추상화.
- **자유도**: 스크립트·플러그인·새 도구 등으로 행동 공간 확장.
- **안전성**: 실행 범위·권한·되돌리기(undo) 정책을 구조적으로 정의.

참고: openclaw의 구체적 스펙이 있으면, 그에 맞춰 어댑터·프로토콜을 매핑하는 계층을 둘 수 있음.

---

## 3. API 두뇌

- **입력**: 사용자 의도, 현재 컨텍스트(화면·파일·에디터 상태 등).
- **처리**: 목적 추출 → 계획 생성 → 도구/API 선택 → 실행.
- **출력**: 로컬 액션(클릭, 타이핑, 파일 수정 등) + API 호출 결과 + 사용자 응답.

KPI·피드백은 NEXUS 작동 원리(평가 영역)에 따라 구조적으로 정의하고, 로그·메트릭으로 피드백 루프에 반영.

---

## 4. 따뜻한 페르소나

- **내부**: NEXUS 원칙 유지. 판단은 근거·구조·데이터 기반.
- **외부(사용자 대면)**: 공감, 인사, 격려, 명확한 설명 등 따뜻한 톤.
- **분리**: “무엇을 할지”(로직)와 “어떻게 말할지”(페르소나)를 레이어로 분리해, 로직은 유지하면서 톤만 조정 가능하게 설계.

---

## 5. 다음 단계

1. **openclaw 연동**: openclaw가 있다면 프로토콜·API 문서 확인 후 통합 제어 레이어 스펙 작성.
2. **도구/API 목록**: 사용할 LLM API, 로컬 스크립트, 외부 서비스 목록 정리.
3. **프로토타입**: 최소 경로(예: CLI 또는 로컬 서버)로 제어 + 지능 + 페르소나 한 사이클 구현.
4. **피드백 루프**: 실행 로그, 사용자 만족도, 작업 완료율 등을 KPI로 정의하고 NEXUS 평가 원칙에 따라 반영.
